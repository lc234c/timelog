# 工时记录

简洁高效的个人工时打卡与统计工具，纯前端零依赖，支持离线使用与 PWA 安装。

- 当前版本：**v2.1.1**（2026-09-02）
- 技术栈：原生 HTML / CSS / JavaScript，无任何第三方库，图表为 Canvas 手绘
- 运行环境：现代浏览器（Chrome / Edge / Safari / Firefox 近两年版本）

---

## 一、功能特性

### 打卡页

| 功能 | 说明 |
| --- | --- |
| 日历 | 月视图 / 周视图一键切换；点击切换日期，**长按 600ms** 快速补卡；已完成为绿色、部分完成为橙色 |
| 白/夜班 | 白班、夜班独立配置，各自记录时段与步骤名 |
| 打卡按钮 | 按进度变色：蓝 → 橙 → 绿 → 灰（四次打满） |
| 今日统计 | 默认展开，四个打卡时段逐条展示，**有记录的行才显示删除按钮** |
| 跨天归属 | 夜班凌晨打卡自动归属到夜班起始日（详见下方规则说明） |

### 统计页

| 功能 | 说明 |
| --- | --- |
| 本月 / 本周 | 总工时、打卡天数、平均工时，跟随日历选中日期实时刷新 |
| 工时趋势图 | 柱状图 / 面积折线切换；范围支持本月 / 本周 / 自定义；点击或触摸查看某日详情 |
| 达标线 | 默认 6h，可自定义（0.5~24h），达标柱体自动转绿 |
| 图表摘要 | 累计工时、较上期环比（🔺/🔻/→）、工作日进度条、日均 |
| 导出与分享 | 「⬇️PNG」点击下载图片，**长按或右键**调用系统分享 |
| 工时记录 | 按日期范围筛选，卡片式展示每日起止时间与当日工时 |

### 设置

- ⏰ 自定义班别时间段（白班 / 夜班各两个时段，即时生效并持久化）
- 📅 月历默认展开开关（决定首屏是月视图还是周视图）
- 🎯 设置每日达标线
- 💾 数据管理：下载备份文件 / 复制备份数据 / 从备份文件导入 / 粘贴导入 / 清空所有数据
- ℹ️ 关于与更新记录、🔄 检查更新

## 二、快速开始

### 本地运行

```bash
# 任选一种
npx serve .
python3 -m http.server 8080
php -S localhost:8080
```

然后浏览器打开 `http://localhost:8080`。

> **不建议直接双击 `index.html`（file:// 协议打开）**。此时 `localStorage` 不可用，数据只存在内存中，刷新即丢失，页面顶部会给出黄色提示。Service Worker 也无法注册。

### 部署

整个目录是纯静态文件，直接上传到任意静态托管（GitHub Pages、Vercel、Netlify、对象存储等）即可。

- 需通过 **https** 或 `localhost` 访问，否则 Service Worker 无法注册
- 更新版本后，修改根目录 `version.json` 的 `version` 字段，Service Worker 会随之创建新缓存并清理旧缓存
- 更新日志维护在 `changelog.json`，修改后无需改动任何 JS

### 图标

`manifest.json` 与 `sw.js` 引用了 `icon-192.png`、`icon-512.png`，仓库中需自备这两个文件，否则 PWA 安装时图标会缺失。

## 三、文件结构

```
.
├── index.html        # 页面结构（含所有弹窗与 Tab 容器）
├── style.css         # 全部样式，iOS 风格设计
├── script.js         # 全部逻辑（v2.1.0 已重构，约 1560 行）
├── manifest.json     # PWA 配置
├── sw.js             # Service Worker：按 version.json 版本号管理缓存
├── version.json      # 当前版本号（检查更新、SW 缓存键均读取此处）
├── changelog.json    # 更新日志数据源（不改动 JS 即可更新）
├── icon-192.png      # PWA 图标（自备）
├── icon-512.png      # PWA 图标（自备）
└── README.md
```

### script.js 分层结构（v2.1.0）

```
常量 → 工具 → 存储 → 状态 → 数据层 → 渲染调度 → 渲染层
     → 业务逻辑 → 事件绑定 → 初始化
```

设计要点：

- **单一数据源**：所有状态集中在 `state` 对象，UI 只是它的投影
- **统一渲染调度**：通过 `invalidate('calendar','stats',…)` 声明脏区，由 `requestAnimationFrame` 合并为一次渲染；一次操作最多重绘一次
- **事件委托**：日历只挂载 5 个监听器（pointerdown/move/up/cancel/leave + click），不再逐格绑定
- **共用绘图引擎**：页面图表与 PNG 导出共用 `paintChart()`，视觉表现天然一致

## 四、数据结构

数据全部保存在浏览器 `localStorage` 中，不会上传任何服务器。

### localStorage 键说明

| 键名 | 内容 | 示例 |
| --- | --- | --- |
| `attendanceData` | 全部打卡记录 | 见下 |
| `shiftSchedules` | 自定义班别时间段 | `{"day":{"periods":[…]},"night":{"periods":[…]}}` |
| `defaultShiftType` | 当前班别 | `day` / `night` |
| `calendarDefaultExpanded` | 月历默认展开 | `1` / `0` |
| `chartTargetHours` | 达标线（小时） | `6` |
| `lastBackupRemind` | 上次备份提醒时间戳 | `1756752000000` |

### 打卡记录格式

```json
{
  "2026-09-01": {
    "shiftType": "day",
    "status": {
      "s1": "08:05:00",
      "e1": "12:01:00",
      "s2": "13:31:00",
      "e2": "17:35:00"
    }
  }
}
```

- `s1/e1/s2/e2` 分别对应「上班—下班」两对打卡，顺序固定
- 时间为 `HH:MM:SS`，`HH:MM` 在导入时会自动补全秒
- **无任何打卡的日期不会写入存储**，因此打卡天数不会被空记录稀释

### 备份与导入

- **下载备份文件**：生成 `工时记录备份_YYYYMMDD_HHMM.json`
- **复制备份数据**：写入剪贴板，失败时弹出文本框供手动复制
- **导入**：选择备份文件或粘贴 JSON，二次确认后覆盖当前数据；导入时会自动清洗非法日期键、非法时间与空记录

> **关于下载的环境限制**：iOS Safari、iOS 桌面 PWA（`display: standalone`）以及微信等 App 内置浏览器不支持 `<a download>` 落盘。这类环境下点「下载备份文件」不会假装成功，而是直接弹出可复制的备份数据并说明原因，确保数据一定拿得到。若需要真正的 .json 文件，请在 Safari / Chrome 中打开本页再下载。

## 五、规则说明

### 夜班跨天归属

夜班常跨越零点（如 19:30 ~ 次日 05:00）。打卡时的归属规则：

- 凌晨 0:00~5:59 打夜班，且日历当前选中的是**今天** → 自动归属到**昨天**（夜班的起始日）
- 若已手动选中昨天或其他日期 → **保持不变**，不会重复回退

### 工时计算

- 单次工时 = 该时段「下班时间 − 上班时间」，跨天自动加 24 小时
- 当日工时 = 前半段 + 后半段
- **统计口径**：月/周统计只累计「工时 > 0」的日期，避免未打卡的日期拉低日均

### 工作日进度

按周一至周五计算，不考虑法定节假日。

## 六、常见问题

**Q：数据存在哪里？会同步吗？**

存在当前浏览器的 `localStorage` 中，不联网、不同步、不跨设备。换浏览器或清理缓存会丢失，请定期备份。

**Q：点了「下载备份文件」，提示已开始下载却找不到文件？**

v2.1.1 已修复该问题。原因是 iOS Safari、iOS 桌面 PWA 与微信等内置浏览器不支持 `<a download>`，旧版本却无条件提示成功。现在这类环境会直接弹出可复制的备份数据。
若仍无反应，请确认版本已升到 2.1.1（修改 `version.json` 后刷新，Service Worker 才会换缓存），并改用「复制备份数据」。

**Q：为什么用 file:// 打开会提示数据只存内存？**

file:// 协议下浏览器禁用 `localStorage`。请用 http 方式打开（`npx serve .` 或 `python3 -m http.server`）。

**Q：误删了某次打卡，能恢复吗？**

不能撤销。可用「设置 → 下载备份文件」中的历史备份导入恢复。

**Q：打卡时提示「不在排班时段内」怎么办？**

说明当前时间不在该班别的时段范围内。点击确认可强制打卡（等同于补卡）。若时段设置与实际不符，请到「设置 → 自定义班别时间段」调整。

**Q：修改了时段后，历史记录的工时变化了？**

不会。工时按实际打卡时间计算，与排班时段无关；时段只影响打卡时的校验与提示。

**Q：更新后页面没变化？**

Service Worker 缓存了旧资源。修改 `version.json` 的版本号后重新访问即可；或手动清除站点数据。

**Q：图表导出成空白？**

该日期范围内没有任何工时大于 0 的记录。请切换到有数据的范围再导出。

## 八、v2.1.0 重构说明

本次为纯重构，功能与交互保持不变，重点解决架构老化与若干隐蔽缺陷。

### 修复的缺陷

1. 点击日历任意日期会生成一条空打卡记录，导致统计天数虚高、日均被稀释
2. `new Date("YYYY-MM-DD")` 按 UTC 解析，东八区下自定义图表范围首尾各差一天
3. 切换白/夜班会在备份数据中留下无打卡的空壳记录
4. 夜班时「今日统计」仍显示白班步骤名（上午上班 / 下午下班）
5. 初始化时图表已切到「本周」，但范围按钮仍高亮「本月」
6. 补卡时允许写入非法日期与非法时间

### 优化项

- 日历改用事件委托 + pointer 事件，监听器数量由每格 7 个（共 200+）降至 5 个
- 一次操作只重绘一次，原先单次打卡会触发 5~6 次图表重绘
- 页面图表与 PNG 导出合并为同一绘制引擎，消除两套重复绘图代码
- 记录列表与更新日志统一 HTML 转义，导入数据自动清洗

完整的版本历史请查看 `changelog.json`，或在应用内「设置 → 关于 / 更新记录」中查看。
